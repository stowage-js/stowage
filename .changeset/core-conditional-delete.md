**Breaking:** `Storage` carries a second form of `delete`, `delete(key: string, options: DeleteOptions): Promise<DeleteReport>`, beside the variadic one, so an adapter written elsewhere that implements `delete` with the variadic signature alone is no longer assignable to `Storage` until it implements the form for one key (spec 15, ADR 0070). `DeleteOptions` extends `OperationOptions` with `onlyIf?: { etag: string }`. Without `onlyIf` the form deletes the key as `delete(key)` does, under the caller's signal; with it, it deletes only the object `etag` describes, in one request never part of a batch, and reports a failed precondition as the key's `PreconditionFailed` entry. `capabilityNames` gains `deleteIfUnchanged`, second in its order. `preconditionRefusal` takes `"delete"` beside `"write"`: there an `onlyIf` object needs `deleteIfUnchanged`, and any string, `"absent"` included, is `InvalidOption` naming `onlyIf` on every storage, since "absent" has no kind on a delete.
