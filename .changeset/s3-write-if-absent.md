`adapter-s3` declares `writeIfAbsent`. `put` with `onlyIf: "absent"` sends `If-None-Match: *`, signed, on `PutObject`, and on a multipart upload on `CompleteMultipartUpload` alone: AWS ignores it on `CreateMultipartUpload` and refuses it on `UploadPart`, and R2 checks it at the start without carrying it to the commit. `copy` and `move` send it on `CopyObject` beside `cf-copy-destination-if-none-match: *`, since AWS holds the one and R2 the other; the delete of `from` in a `move` stays unconditional. `presignPut` signs it and hands it back in `headers` as `if-none-match`, and never as the query parameter R2 ignores. A key that holds an object rejects with `PreconditionFailed`, `key` set to `to` for `copy` and `move`, and so does AWS's `409 ConditionalRequestConflict` for a commit another writer overtook. A commit its precondition refused leaves the key as it was and aborts the upload, which AWS would otherwise let a later commit without the header complete. A refusal after an attempt without a response or with a `5xx` rejects with that earlier failure, since the repeat of a write that went through meets its own object; a conditional commit repeated after a `5xx` reads R2's `NoSuchUpload` the same way, and a commit that received no response is still not repeated. `onlyIf: { etag }` stays `Unsupported` naming `writeIfUnchanged` (ADR 0071, ADR 0073, ADR 0074).
