`adapter-azure-blob` declares `writeIfUnchanged` and `deleteIfUnchanged`. `put` with `onlyIf: { etag }` sends `If-Match` with the `etag` quoted as a strong tag on `Put Blob`, and on a block upload on `Put Block List` alone. `copy` and `move` send it on `Put Blob From URL` beside the pin of the source; the delete of `from` in a `move` stays unconditional. A key that holds another blob, or none, rejects with `PreconditionFailed` from Azure's `412 ConditionNotMet`, `key` set to `to` for `copy` and `move`. `delete(key, { onlyIf: { etag } })` sends one `Delete Blob` carrying `If-Match` rather than a Blob Batch, and reads its answer as that key's entry: a blob that changed is a `PreconditionFailed` entry, and so is a `404 BlobNotFound`, which is no success under a precondition, while a `404 ContainerNotFound` still rejects as the missing container. A refusal after an attempt without a response or with a `5xx` is the entry of that earlier failure, `retryable: true`, since whether this call deleted the blob is open. `presignPut` keeps `sp=w`, appends `if-match` to `srh` after the content headers and hands it back in `headers` with the quoted `etag`. Since the capabilities promise `etag`, an answer that describes an object without `ETag`, a listing entry among them, is `ProviderError` (ADR 0071, ADR 0073, ADR 0074).
