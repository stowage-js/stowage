`adapter-azure-blob` declares `writeIfAbsent`. `put` with `onlyIf: "absent"` sends `If-None-Match: *` on `Put Blob`, and on a block upload on `Put Block List` alone, since Azure checks no precondition on `Put Block`. `copy` and `move` send it on `Put Blob From URL` beside the pin of the source, again on the repeat after a failed pin, which stays `CannotVerifyCopySource` and never becomes `PreconditionFailed`; the delete of `from` in a `move` stays unconditional. A key that holds an object rejects with `PreconditionFailed`, `key` set to `to` for `copy` and `move`: Azure answers it `409 BlobAlreadyExists` where it documents `412`. A commit its precondition refused leaves the key as it was and the staged blocks as any stopped block upload does. A refusal after an attempt without a response or with a `5xx` rejects with that earlier failure, since the repeat of a write that went through meets its own object. `presignPut` binds `"absent"` through the permission, `sp=c` in place of `sp=w`, which Azure refuses an upload onto an existing object under with `403`; neither `srh` nor `headers` changes (ADR 0071, ADR 0073, ADR 0074).
