`@stowage/http` joins the family as the HTTP layer (spec 10, ADR 0046, ADR 0048). `serveObject(storage, key, request, options?)` answers `GET` with the stream of `get` and `HEAD` from `stat`, each with `Content-Type`, `X-Content-Type-Options: nosniff`, `Content-Disposition`, `Cache-Control`, `ETag`, `Last-Modified` and, where the storage declares `rangeReads`, `Accept-Ranges`, and no `Content-Length`; any other method is `405`. Where the storage declares `rangeReads`, one range of `bytes`, a suffix range included, is `206` with `Content-Range` and `Content-Length`, an unsatisfiable one `416` with `Content-Range: bytes */<size>`, and a ranged `get` refused with a `ProviderError` that is not retryable is followed by one whole `get`; several ranges, another unit, a malformed header and `Range` on a `HEAD` are ignored. A `StorageError` becomes the status of spec 10.2 with an empty body, and `storageErrorOf(response)` answers the error behind it. `If-Match`, `If-Unmodified-Since`, `If-None-Match`, `If-Modified-Since` and `If-Range` are evaluated in the order of RFC 9110 13.2.2: a failed `If-Match` or `If-Unmodified-Since` is `412`, a failed `If-None-Match` or `If-Modified-Since` `304` with the headers of the `200`, and `If-Range` serves the range for the strong `ETag` alone. Only a request carrying a precondition or a suffix range calls `stat` before `get`, and where the object changed in between, the answer follows the `stat` of `get`. `redirectToObject(storage, key, request, { expiresIn, filename?, disposition? })` answers `GET` and `HEAD` with the same `302` to a URL from `presignGet`, with `Cache-Control: private, no-store` and an empty body, and passes `expiresIn` and the `Content-Disposition` of `serveObject` on as `responseContentDisposition`; it takes `PresignsGet`, which `S3Storage`, `AzureBlobStorage` and a `GcsStorage` built with a `signer` satisfy and a storage without `presignedUrls` does not. `presignUpload(storage, key, { expiresIn, maxSize, contentType, contentLength })` answers `200` with `Content-Type: application/json`, `Cache-Control: private, no-store` and the body `{ url, method: "PUT", headers }` from `presignPut`; it takes no `Request`, and before signing refuses a `contentLength` that is no non-negative integer with `400`, one above `maxSize` with `413`, and a `contentType` that is empty or no valid header value with `400`. It takes `PresignsPut`, which the same storages satisfy as `PresignsGet`. `toWebRequest` and `writeResponse` carry a web `Request` and `Response` over `node:http` without importing a `node:` module. Accepting an upload follows.
